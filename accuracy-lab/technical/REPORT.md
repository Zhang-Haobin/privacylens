## 浏览器端脱敏算法

1. 从原始 OCR 数据构造只含行 ID、词 ID、文字和归一化词框的请求副本。原始文字、词 ID 和本地框保持不变。
2. 在行级文字中查找带赋值符的凭据标签、认证头、带认证信息的连接串和部分常见密钥前缀。可疑内容定位到实际 OCR 词 ID；同一个词含标签和值时替换整个词，不伪造字符坐标。
3. 对被拆成多个词的值收集所有相关词；对可能的续行采用保守整词处理。使用临时的去空白字符映射查找同一已发现值的重复出现。PEM 私钥区域按块排除。
4. 将命中的词替换为 `[SECRET_TOKEN1]`、`[SECRET_PASSWORD2]` 等类型占位符。线上副本采用字段白名单，不复制 `line.text`、额外原文或任意 OCR 属性。
5. 脱敏独立于用户的图片 Hide/Keep 选择；即使用户主动显示某个凭据，发送副本仍进行筛查。没有“筛查失败后发送原文”的回退。
6. 服务端验证请求后再做一次筛查，提供直接文本调用的额外保护。无效 ID 触发的至多一次重试复用同一份筛查后文本。现有客户端只调用文本分类端点，不会回退到图像端点。

支持的候选包括 API key、access/refresh/auth/session token、client secret、password/passwd/pwd、private/secret key、Authorization/Basic/Bearer、Cookie、DATABASE_URL/connection string/DSN、部分中文及门禁/验证码标签、PEM 私钥，以及有限的常见密钥前缀。标签需要赋值语法；不会仅因出现“token”或随机字符串就判为凭据。显式配置连接串会保守筛查，即使不能确认其中是否含密码。

局部文件路径支持 `/Users/...`、`/home/...`、`C:\Users\...`，按完整 OCR 词框遮挡。内部域名后缀、内部主机前缀和 RFC1918 地址产生 Needs Review，默认遮挡；它们的格式本身并不证明保密性。localhost、公开文档 URL、通用系统目录、独立错误信息、方法名、版本和行号不因技术场景而自动遮挡。

## 类型、目的与示例

技术类型使用现有独立证据组计数：异常/traceback、堆栈行、终端命令、诊断错误、技术配置和运行时版本。至少两个证据组且无最高分并列才建议类型；不足或混合时仍回到 General。已有的手动类型更正机制保持不变，不使用文件名或远程请求分类。

三个快捷任务为 Public forum / Ask for technical help online、Official support / Contact software support、Teammates / Debug with colleagues。凭据在三者中始终建议 Hide；个人路径建议 Hide，内部网络信息建议 Review；软件客服需要的账号标识也需要人工 Review。Custom 继续使用保守规则，不由 AI 解释自由文本。

新虚构示例含 Node.js 版本、TypeError、独立堆栈与行号、合成 API key、个人路径、示例邮箱、内部主机和公开文档 URL。示例的预标注区域明确披露；OCR 如无法可靠匹配，会沿用已有的保守区域保留机制，可能显示重叠候选供复核。

## 独立源标注图片评估

14 张图片：10 张技术场景，以及聊天提及错误、公开文档讨论 token、通用目录和随机字符串四种负例。共 22 个需要隐藏或复核的源字段，其中 14 个为凭据；另有 42 个应保留的控制区域。标注由虚构源字符串与固定字格几何在 OCR 前生成，与检测器和 OCR 词框无关；已视觉检查代表性源图和输出。

使用真实 Tesseract English 双遍识别。基线和新规则使用相同 OCR 数据；比较包含现有政策和最终框生成。完整覆盖定义为标注区域内至少 99.5% 的原始深色文字像素落在遮挡框中；部分覆盖为大于零但未达此阈值。控制区覆盖超过 5% 计为误遮挡。这里不是人工收集的真实世界或严格保留的盲测集，开发中修复了域名拆词和续行误判。

## 实际请求与重试

使用真实浏览器 editor → localhost HTTP POST → 真实 `handleAI`；provider 的 fetch 传输由本地测试 stub 接管。对内置技术示例、独立终端图片、OCR 拆词的数据库配置图片各完成一次分类请求，共捕获 3 次浏览器 POST 和 6 份 provider 请求体。

- 3/3 浏览器请求不含已知合成凭据原文；检查同时覆盖序列化正文及跨词拼接内容。
- 6/6 provider 请求体不含这些凭据；每次首个模拟结果使用无效 ID，确实触发一次重试。
- 3/3 重试的用户文本与第一次完全相同，均使用筛查后副本。
- 在独立终端图中主动显示凭据、调整框后运行 AI，实际发送副本仍替换凭据。
- 没有选择同意时按钮不可用；接口无 consent 时拒绝请求。

这些验证不联系真实模型服务，不衡量模型分类能力，也不证明未知格式、漏识别或误识别的凭据一定被发现。`results/browser-request-captures.json` 记录了安全的实际正文及布尔检查结果；失败时测试服务不会保存不安全正文。

## 回归与限制

- `npm test`：105/105 通过，包含原有订单、地址、学术、聊天、付款、框定位、用户选择和 API 合同测试。
- 原有 9 图本地真实 OCR 检查：21/21 通过。
- 在原有独立评估保存的 15 份 OCR 文档上重放：15/15 类型不变，原有遮挡像素丢失为零；这不是重新进行全套真实模型调用。
- JS 语法及 `git diff --check` 通过。没有修改 OCR 算法或几何编辑器。

仍有边界：OCR 会漏掉或误读文字，未知凭据格式及超过保守续行范围的长值可能漏检；某些续行/连接串会整词、整行过度遮挡。内部网络判断是启发式，路径不提供字符级精确遮挡。姓名、地址、未命中的凭据等仍可能进入同意后的文本请求，脱敏不等于匿名化。截图遮挡不会撤销已经泄露的凭据。

原有显式同意的 legacy 图像接口仍作为兼容端点存在，不由当前编辑器调用，也不属于本阶段文本脱敏保证。当前页面没有原文或图像自动回退请求。真实 provider 新字段表现、混合语言技术截图、小字/旋转/低对比截图和更大真实世界数据集尚未验证；未部署到 Vercel。Phase 2 付款与退款场景尚未开发。
